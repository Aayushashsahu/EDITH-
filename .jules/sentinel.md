## 2024-05-22 - PowerShell Command Injection via `_ps` Bridge
**Vulnerability:** Command injection was possible in `SystemControl.notify` and `SystemControl.hotkey` because user inputs (`title`, `body`, and `keys`) were dynamically interpolated into PowerShell strings enclosed in single quotes without escaping those single quotes. An attacker could break out of the string context by supplying input containing single quotes and execute arbitrary PowerShell commands on the host system.
**Learning:** The application uses a custom `_ps` bridge which passes a single string command to `powershell.exe -Command`. When interpolating variables into PowerShell single-quoted strings, any single quote within the variable must be explicitly escaped by doubling it (`''`) to ensure PowerShell parses it strictly as a literal string value instead of executing code.
**Prevention:** Always sanitize strings injected into `_ps` command strings. If the string is enclosed in single quotes within the script block, use `.replace("'", "''")` before interpolating the value. Ensure all functions passing user data to `_ps` follow this pattern (e.g., `open_url`, `type_text`, `notify`, `hotkey`).
