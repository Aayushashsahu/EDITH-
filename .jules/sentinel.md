## 2024-05-28 - [Command Injection via Windows CMD Bridge]
**Vulnerability:** Command injection vulnerability in WSL-to-Windows `_cmd` execution bridge when untrusted input (e.g., URLs) is passed to `WIN_CMD /c start {url}` without sanitization.
**Learning:** `cmd.exe` easily executes injected commands (via `&` or `&&`), making naive string interpolation extremely dangerous when crossing the OS boundary from WSL to Windows.
**Prevention:** Avoid `_cmd` for untrusted input. Instead, use the PowerShell bridge (`_ps`), enclose inputs strictly in single quotes, and escape any internal single quotes (`replace("'", "''")`) to ensure literal string evaluation.
## 2024-05-31 - [Command Injection via Windows CMD Bridge in open_app and close_app]
**Vulnerability:** Command injection vulnerability in WSL-to-Windows `_cmd` execution bridge when untrusted input (application names) is passed to `WIN_CMD /c start {app}` or `taskkill /F /IM {app}.exe` without sanitization in `SystemControl.open_app` and `SystemControl.close_app`.
**Learning:** `cmd.exe` easily executes injected commands, making naive string interpolation extremely dangerous when crossing the OS boundary from WSL to Windows. Unsanitized strings in these system commands allow arbitrary command execution.
**Prevention:** Avoid `_cmd` for untrusted input. Instead, use the PowerShell bridge (`_ps`), enclose inputs strictly in single quotes, and escape any internal single quotes (`replace("'", "''")`) to ensure literal string evaluation. For `close_app`, input validation against an allowlist pattern (`^[\w\.-]+$`) is an alternative to ensure the input cannot contain injection characters.
